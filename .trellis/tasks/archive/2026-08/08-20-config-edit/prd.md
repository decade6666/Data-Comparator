# 项目编辑：改名 + 导入模板覆盖参数

## Goal

在项目列表中每个项目名称旁增加「编辑」按钮，点击后打开编辑弹窗，可修改项目名称，并可导入内置模板（TM / CIMS）覆盖当前项目参数。

## Requirements

- 项目列表（ConfigSidebar）每个项目行名称旁新增「编辑」按钮（EditPen 图标，title/aria-label「编辑项目」）。
- 点击「编辑」打开编辑弹窗：
  - 弹窗标题「编辑项目」。
  - 项目名称输入框预填当前项目名，可修改。
  - 底部保留「导入模板」下拉（与新建弹窗一致）：导入 TM / CIMS 模板后覆盖当前项目参数（含模板参数，不含已上传文件；文件引用保持不变），并给出成功提示。
  - 确认后调用后端改名端点完成改名。
- 改名规则：
  - 名称不能为空（与新建弹窗一致）。
  - 改名目标不能与现有项目重名（409，前端提示）。
  - 内置模板不可作为改名目标（400，前端提示）。
- 改名成功后刷新项目列表并选中新名称。
- 后端新增改名端点，行为与复制端点一致（内置模板保护、存在性校验）。

## Acceptance Criteria

- [ ] 后端 `POST /api/configs/{name}/rename`（body `{"new_name": ...}`）成功改名；目标重名返回 409；目标是内置模板返回 400；源不存在返回 404。
- [ ] 前端每个项目行有「编辑」按钮，点击打开「编辑项目」弹窗，名称预填。
- [ ] 弹窗可导入模板覆盖参数（不丢已上传文件引用），有成功提示。
- [ ] 确认改名后列表刷新、新名称被选中；重名/内置模板时报错提示。
- [ ] pytest 与 vitest 全绿；浏览器 E2E 验证编辑改名 + 模板覆盖流程。

## Notes

- 复用 `NewConfigDialog` 弹窗逻辑（名称输入 + 导入模板），通过 prop 区分「新建 / 编辑」模式。
- 现有 `useConfigState` 有 `openNewConfigDialog` / `resolveNewConfigDialog` 的 Promise 模式，编辑弹窗沿用同一机制以最小化改动。
- 后端无配置改名端点，需新增；参照 `copy_config` 的校验模式。
- 用户可见文案用「项目」（前端已全局改名），API 路由用 `/api/configs`。
