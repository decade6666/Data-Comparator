# 比对操作区重构 + 历史记录

## Goal

把比对页面的操作收敛到底部一张吸底操作卡片，突出「开始比对」，完成后自动交付报告与日志；并补上真正的历史记录能力（后端持久化 + 日志落盘 + 历史报告/日志下载），让用户随时能取回自己的比对结果——目前结果文件虽然永久留在 `users/<id>/results/`，但任务记录 30 分钟后即被内存清扫，文件变成无法取回的孤儿；日志则从不落盘，刷新页面即丢失。

## Requirements

R1. 新增底部「操作」卡片，吸底固定（`position: sticky; bottom: 0`），承载：开始比对 / 停止比对、下载报告、下载日志、历史记录、保存项目、取消保存。进度卡片、比对参数卡片中原有对应按钮随之移除。
R2. 开始比对按钮大而醒目：带文字、`size="large"`、高度 44px、最小宽 180px、复用设计令牌（`--shadow-primary`、`--radius-md`、`--font-md`），支持暗色模式；停止比对复用同尺寸（`type="danger"`）。
R3. 保存项目 / 取消保存 改为图标按钮（`FolderChecked` / `RefreshLeft`），悬停即时显示中文提示（`<el-tooltip>`），保留 `aria-label`。
R4. 比对完成后自动下载：`completed` → 报告 + 日志（串行，报告优先）；`failed` → 仅日志；`cancelled` → 不下载。设置面板新增开关，默认开启。被浏览器拦截时弹警告提示手动下载，不得静默失败。
R5. 历史记录按钮（`Clock` 图标）打开弹窗：按时间倒序列出当前项目的历次比对（日期时间、文件名、状态），提供报告与日志下载按钮（不可用时禁用），每行可展开显示当次比对参数与结构设置。
R6. 后端持久化每次比对的记录（新表 `comparison_run`），任务结束后落库，含完整参数快照（剥离绝对路径与 upload id）、起止时间、状态、错误信息、报告/日志文件名。
R7. 后端落盘日志文件：`{项目名}-比对日志-{YYYY-MM-DDTHH-MM-SS}.txt`，与报告共用同一时间戳、同在 results 目录；失败/取消任务也有日志（报告没有）。
R8. 历史列表接口按 `config_name` 过滤、`limit` 收敛（默认 20，上限 100）；详情接口返回参数快照；报告/日志下载接口按记录 id 取文件，独立于内存 JobManager，服务重启后仍可下载。

## Out of Scope

- 结果文件自动清理/保留策略（本次不新增任何删除用户文件的逻辑）。
- 上线前存量报告的回填（文件名经 `sanitize_output_name` 处理，反推项目名不可靠）。
- 记录 `POST /api/compare`（遗留同步接口，前端不用）。
- 「全部项目」历史视图（API 的 `config_name` 设为可选，为后续留口）。
- 保留策略的管理端 UI。
- 修改 `src/backend/domain/data_comparison.py`。

## Acceptance Criteria

- [ ] 底部操作卡片吸底：滚动比对参数列表时开始比对始终可见。
- [ ] 进度卡片不再含任何操作按钮；比对参数卡片底部不再含保存按钮。
- [ ] 开始比对按钮带「开始比对」文字、`size="large"`、`.action-start-btn` 类；悬停有抬升效果，暗色模式下阴影正确。
- [ ] 保存/取消保存为图标按钮，悬停即时（非 ~1s 延迟）显示中文提示，无 title 双重气泡。
- [ ] 比对完成后自动触发下载：completed 恰好各触发一次报告与日志；failed 只触发日志；cancelled 不触发。开关关闭时不触发。下载 reject 时弹出警告且不抛未捕获异常。
- [ ] 历史弹窗按时间倒序显示当前项目历次比对：时间、文件名（省略+悬停全名）、状态标签；`report_available=false` 时下载报告禁用；展开行显示参数与结构设置。
- [ ] 服务重启后历史仍在且可下载（新增记录经 SQLite 持久化）。
- [ ] 项目改名后历史记录跟随新项目名；复制项目不迁移历史。
- [ ] 成功后 results 目录同时出现成对文件：`{项目}-比对报告-{ts}.xlsx` 与 `{项目}-比对日志-{ts}.txt`，时间戳逐字节一致。
- [ ] 失败任务的记录 `status="failed"`、无报告文件名、有日志文件名与错误信息。
- [ ] 用户 B 对用户 A 的历史记录 id 请求得 404（而非 403），列表互不可见。
- [ ] 硬删用户时对应历史行一并删除。
- [ ] 后端 pytest 全绿（含覆盖率不低于 80% 且不下降）；前端 vitest 全绿；`npm run build` 通过。
- [ ] 帮助弹窗内「开始比对 / 保存项目 / 下载日志」相关指引文案更新为新位置，并新增历史记录与自动下载说明；README / CLAUDE.md 端点清单同步。

## Notes

- 自动下载多文件拦截：串行（报告 → 800ms → 日志），报告优先。
- 历史行只存文件 basename，绝不存绝对路径；下载时 `os.path.join(results_dir, basename)` + `is_safe_path` 双重防护。
- `comparison_run.user_id` 为普通 Integer 不设 FK（`PRAGMA foreign_keys=ON` 下配 `session.delete(user)` 会抛异常）；沿用 `RecycledConfig.original_owner_id` 先例。
- 顺带修复既有 `_user_active` 泄漏 bug：取消排队中任务后 `_user_active` 永不清理，用户此后永远 409。
